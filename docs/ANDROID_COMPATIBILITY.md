# Android compatibility notes

支持范围为 Android 10 / API 29 至当前测试的 Android 16 / API 36，`minSdk 29`、`compileSdk 35`、`targetSdk 35`。

## 系统版本

- Android 10：后台定位可在独立运行时权限请求中授予。
- Android 11–16：前台精确定位成功后，应用把用户引导到系统应用详情页选择“始终允许”；不会把前台与后台定位放进同一次请求。
- Android 13–16：通知是开始记录的硬性条件。系统或用户关闭通知后，首次启动会被禁用，持久服务恢复也会安全停止并把会话标记为中断。
- Android 14–16：Manifest 声明 `FOREGROUND_SERVICE_LOCATION`，Service 标记 `foregroundServiceType="location"`，并只从可见 Activity 首次启动。

仅授予大致位置不满足应用要求。不同厂商可能把“精确位置”表示为权限页中的独立开关。

## 记录模式

- `endurance` / 耐力模式：默认使用平衡精度，目标间隔默认 4 分钟并可在 1–5 分钟内调整，适合长时间记录。
- `precision_walk` / 精细步行：固定使用高精度，目标 10 秒、最短 5 秒、最长批处理延迟 15 秒，适合植物园、公园和短时小范围路线。该模式会持续使用 GNSS，耗电明显增加。

模式和全部间隔参数在会话开始时固化；历史导出不会因之后修改设置而改变。精细步行的轨迹密度仍受天空遮挡、室内失锁和厂商后台策略影响，应用只记录系统实际返回的位置，不插造中间点。

## 厂商后台策略

- Samsung / One UI：应用信息 → 电池 → 不受限制；设备维护 → 电池 → 后台使用限制 → 从不休眠的应用。
- Xiaomi / HyperOS：允许自启动，电池策略选择无限制，并锁定最近任务（如系统提供）。
- OPPO / OnePlus / realme：允许后台活动和自启动，关闭针对 GPSLog 的自动优化。
- vivo / OriginOS：允许高耗电后台运行与自启动。
- Huawei / HarmonyOS：应用启动管理改为手动，允许自启动、关联启动和后台活动。
- Pixel / AOSP：应用电池用量选择“不受限制”可获得最稳妥的长时记录；系统通常不需要额外厂商白名单。

应用不会尝试私自写厂商设置，也不会持有持续 WakeLock。SM-S9180 实测表明，Android 通用电池优化白名单不能替代 One UI 的“从不休眠的应用”：锁屏后用非用户可见的测试入口冷启动前台服务时，Samsung Freecess 仍可能冻结进程。正式使用必须从可见首页开始记录，并完成 Samsung 两项后台设置。

耐力模式超过 5 分钟没有新点时使用系统唤醒闹钟；已加入电池优化白名单的设备可按时执行精确补救，其他设备会使用免特殊权限的非精确 Doze 闹钟并由系统批处理。启动和补救一进入事务就先排好下一次闹钟，即使厂商在定位请求中途冻结进程，仍保留后续系统唤醒入口。Play services 定位 `Task` 自身取消被隔离在受监督的子协程中，不会连带取消停止或救援事务。高精度补救期间的短时 WakeLock 最长 35 秒；若进程只为停止命令而重建，会跳过最终定位并优先持久结束会话。系统强制停止、用户关闭定位、权限撤销和设备重启均可能中断记录；导出中的 `gapCount` 和时间间隔会如实反映缺口，不伪造轨迹。

## 换机检查

新设备安装后应完成一次 60–90 分钟耐力模式预检：熄屏、回桌面、打开其他应用、进入 Doze，测试通知精准打点和停止，再确认导出 JSON 可通过 `gpslog-geotag doctor`。还应在露天步行 10–20 分钟测试精细步行模式，确认相邻点密度和功耗符合该设备预期。完整拍摄前建议把系统时钟和相机时钟对齐，或用一张拍摄了可靠时钟的照片测量 `--clock-offset`。

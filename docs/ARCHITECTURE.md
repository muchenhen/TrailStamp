# 架构与设计取舍

GPSLog 包含两个可以分别构建的组件。Android 负责记录与导出，Rust 消费导出的轨迹，
完成时间匹配、预览和经校验的副本写入。共享边界是 `gpslog.track/v1` JSON，
而不是某一台手机、某个文件夹或一个固定服务器。

## Android

`LocationRecordingService` 管理定位与前台通知。Room 保存会话和位置点，DataStore
保存设置与活动会话引用。记录模式的参数固化在会话快照中，之后修改设置不会改写旧会话含义。

耐力模式偏向平衡精度和批处理；精细步行模式请求更密集的高精度位置。定位缺口、精度不足、
mock 点和设备重启都有明确记录，不通过伪造中间点填补路线。
服务恢复、厂商后台冻结和定位请求取消的处理见 [兼容说明](ANDROID_COMPATIBILITY.md)。

`TrackExporter` 生成 JSON、GPX 和 CSV。Android 导出器的一个测试直接比对共享 JSON fixture，
用于防止导出格式悄悄偏离 Rust 的输入契约。

行政区解析与轨迹上传均为可选功能。上传通过 WorkManager 排队，使用 HTTPS、有限重试和
独立保存的凭据，不向一个写死的公共服务发送数据。

## Rust

| 模块 | 职责 |
| --- | --- |
| `track.rs` | 输入质量、可用点筛选、插值/外推、置信度与异常速度 |
| `timeutil.rs` | 相机本地时间、显式时区、钟差、DST 与 UTC 转换 |
| `site.rs` | 网站照片匹配、路径约束和原子 JSON 写入 |
| `report.rs` | 预览 HTML、执行计划与摘要 |
| `apply.rs` | 输入预检、RAW 副本写入、回读与网站事务恢复 |
| `exiftool.rs` | 固定版本的 Windows ExifTool 校验、解包和进程调用 |

`inspect` 只读取轨迹，便于在任何开发平台试用核心匹配算法。
`preview` 读取 RAW 与网站元数据，生成可审查的计划；`apply` 才执行写入。

将预览与执行分开会增加一步操作，但可以在写入前看到不确定匹配和覆盖冲突。
计划固定输入哈希；如果用户在预览后替换了照片、轨迹或网站 JSON，执行应拒绝过期计划。
位置写入采用副本和回读验证，网站更新则有独立的备份/回滚边界。

ExifTool 作为独立进程运行，Windows 归档固定版本与 SHA-256，运行时不下载工具。
这使照片操作可在离线环境中执行，但当前 RAW 命令也因此只支持 Windows。

## 当前边界

- CLI 的 RAW 预览仍要求网站 JSON 目录参与匹配；尚未拆出完全独立的网站无关 RAW 模式。
- 自动上传的兼容服务端不在此仓库中；Android 本地记录与导出不依赖它。
- 没有地图编辑器、iOS 客户端或 Play 商店发布流程。
- 尚未完成可推广到各类手机的完整户外 8 小时续航与精细步行密度验收。

验证范围以 [VALIDATION.md](VALIDATION.md) 为准，不能从某个单元测试推断整个设备工作流已验收。
